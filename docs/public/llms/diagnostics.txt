DIAGNOSTICS
===========

Read errors, warnings and analyzer suggestions from saved C# files.
Start with the files affected by the task. To check that the MCP works,
request diagnostics for one known C# file.

One file:
diagnostics {"file":"src/Calculator.cs"}

Matching files in one project:
diagnostics {"file":"src/Core/**/*.cs","limit":200}

All C# files, only for a requested workspace audit:
diagnostics {}

Use a specific path or narrow glob. Braces check several files in one call:
diagnostics {"file":"src/{Calculator,Program}.cs"}
Omitting file, using "*" or "**/*.cs" selects all C# files. Split large audits
by project or directory.

severity sets the lowest reported severity. The default, warning, reports
errors and warnings. Use information or hint to include analyzer suggestions:
diagnostics {"file":"src/Calculator.cs","severity":"hint"}

Only some codes. Codes match without regard to case, and ids applies before
severity:
diagnostics {"file":"src/Calculator.cs","ids":["CS0246","IDE0005"]}

One line per code, for a large audit:
diagnostics {"file":"src/Core/**/*.cs","summary":true}

RESULT
------
Results are text lines. Each file with diagnostics is followed by one
indented line per diagnostic:
src/Calculator.cs
  12:9 error CS0246 The type or namespace name 'Foo' could not be found

12:9 is the one-based line and character of the start. Pass them unchanged
to the edit tool's code_actions, or pass the code as its diagnostic.
severity is error, warning, information or hint. Clean files are not listed.

A totals line follows the files:
4 files checked, 3 diagnostics in 2 files, 5 below the severity
"below the severity" counts diagnostics left out by the severity filter.
A clean scan reads: 1 file checked, no diagnostics

With ids, the report lists and counts only matching diagnostics, and the
totals line ends with "filtered by ids". A filtered scan with no match reads:
1 file checked, no diagnostics, filtered by ids
That is not a clean file. Other codes may remain.

With summary, each code gets one line instead of one line per diagnostic, sorted
by count and then by code:
CS0246 x12 error src/Calculator.cs:12:9 The type or namespace name 'Foo' could not be found
x12 is the count. The severity, an example location and its message follow. The
totals line still counts diagnostics.

A line starting with "truncated:" means the limit omitted diagnostics.
A line starting with "incomplete:" lists files Roslyn has not attached to a
project. These files get no semantic diagnostics. A file outside every project
stays listed. Check the project file includes it.

LIMITS AND VERIFICATION
-----------------------
limit defaults to 50 and accepts 1 through 250 across the whole response.
It caps returned items, not the files analyzed or the analysis time. With
summary, it caps the code lines.
A truncated result gives the next offset. Send it as offset to skip that many
diagnostics, or code lines with summary. Diagnostics are in file, line and
character order, so pages do not overlap. offset never changes the totals.
A scan accepts at most 1000 files. Narrow the glob if it exceeds this limit.
When the result is truncated, split the selection into narrower requests.
Report the checked scope. A failed, incomplete or truncated response cannot
establish that the workspace is clean.
After writing files yourself, rerun diagnostics on them. An edit applied
through the edit tool already reports the diagnostics of its changed files.
A clean diagnostic report does not replace tests or validate runtime behavior.

After a timeout, narrow the selection. If a single-file retry also times out,
report the failure and stop retrying that request.
Attribute the cause only when logs support it.
