## Install

Prerequisites: the .NET 10 SDK and a Model Context Protocol (MCP) client such as Claude Code, Codex, GitHub Copilot CLI, pi or Antigravity.

The bridge is a .NET tool on [NuGet](https://www.nuget.org/packages/ThomasFazzari.RoslynBridge).

<Aside type="caution" title="Install script before 2.0">
  If you installed the bridge with the former install script, delete `roslyn-bridge-mcp` from
  `~/.local/bin` or `%LOCALAPPDATA%\Programs\roslyn-bridge-mcp`, then install the .NET tool and
  register it again.
</Aside>

```sh
dotnet tool install --global ThomasFazzari.RoslynBridge
roslyn-bridge-mcp setup
```

Setup installs the official Roslyn language server as a global .NET tool when it is missing. It then prints the command that registers the bridge in each agent it detects, for example:

```sh
claude mcp add --scope user roslyn -- ~/.dotnet/tools/roslyn-bridge-mcp
```

Run the printed command once per agent. To update, run `dotnet tool update --global ThomasFazzari.RoslynBridge`. The command path stays the same, so the registrations keep working.

Your C# project can target a different .NET version. Keep its required SDK and workloads installed, including any SDK pinned in its `global.json`.

### Without installing

To run the tool without installing it, let the client start it with `dnx`, pinned to a release. Run `setup` once in a terminal:

```sh
dnx ThomasFazzari.RoslynBridge@VERSION --yes -- setup
```

The first run downloads the package and writes a line to standard output that would break a client. `setup` then installs the Roslyn language server and prints registration commands that start the bridge with `dnx`, for example:

```sh
claude mcp add --scope user roslyn -- dnx ThomasFazzari.RoslynBridge@VERSION --yes
```

To update, do the same with the new version.

## Use it

Restore your C# solution with `dotnet restore`, then open a new agent session in that project.
In the CLI, use `/mcp` to check that `roslyn` is connected.

```text
Use the Roslyn MCP to report diagnostics for a C# file, find definitions and
implementations, then preview a rename and a suggested fix. Do not apply changes.
```

Approve the tool call if prompted. The bridge uses the session's working directory as its workspace.
Save editor changes before requesting diagnostics.

## Agent instructions (recommended)

Agents keep their text-search habits, so add these lines to the project's agent instructions, such as `AGENTS.md` or `CLAUDE.md`:

```markdown
## C# code navigation

Use the `roslyn` MCP tools for C# code before text search or reading whole files. If your client defers MCP tools, load them first.
Send independent lookups of known symbols in one `bulk_navigate` call.
Read a whole file only to edit it.
```

Do not describe the tools there. The server already sends their descriptions and usage instructions when the client connects.

## Configuration

In Claude Code, add `mcp__roslyn__*` to `permissions.allow` to run the tools without prompts.
See [Claude Code MCP](https://docs.claude.com/en/docs/claude-code/mcp) and [Codex MCP configuration](https://developers.openai.com/codex/mcp/) for client settings and tool approvals.

The bridge starts loading Roslyn at launch when a `.sln`, `.slnx`, `.slnf` or `.csproj` file sits up to two folders below the workspace root, outside folders such as `bin` and `obj`. Otherwise Roslyn loads on the first request.
A call waits up to the startup timeout, then returns the error `loading` while the load goes on. The error and `lsp` with `action=status` show the load progress.
For large projects, set `tool_timeout_sec = 200` under `[mcp_servers.roslyn]` in Codex.
In Claude Code, set the `MCP_TOOL_TIMEOUT` environment variable in milliseconds, for example `200000`.

| Bridge argument     | Default                                                       |
| ------------------- | ------------------------------------------------------------- |
| `--workspace`       | Current working directory                                     |
| `--server`          | `roslyn-language-server` on `PATH`, then in `~/.dotnet/tools` |
| `--dotnet-root`     | The .NET install that runs the bridge                         |
| `--startup-timeout` | 120 seconds                                                   |
| `--request-timeout` | 60 seconds                                                    |
| `--exclude`         | None. Repeat it to add folders to the built-in list           |

A project can also set these in [`.roslyn-bridge.json`](settings.mdx) (the argument wins).

Timeout arguments accept 1 to 600 seconds. When you raise these limits, keep the client's tool timeout above the sum of the startup and request timeouts.

Roslyn runs on the .NET install that runs the bridge, which needs a .NET 10 runtime and an SDK. Pass `--dotnet-root` to use another install.

MCP clients often start the bridge without your shell environment. On macOS and Linux, when .NET is outside its default or registered location, `setup` prints a command that sets `DOTNET_ROOT`.

## Remove

Remove the `roslyn` entry from each agent with its `mcp remove` command, for example `claude mcp remove roslyn --scope user`. Then run `dotnet tool uninstall --global ThomasFazzari.RoslynBridge`.
