The bridge ships as one framework-dependent .NET tool package, `ThomasFazzari.RoslynBridge`, for every platform. `src/RoslynBridge/RoslynBridge.csproj` defines its metadata. The build workflow in `.github/workflows/ci.yml` runs the unit and integration tests on Linux, macOS and Windows, and packs the tool once.

## Publishing

Tag a commit of `master` whose `ci-ok` check passed, and push the tag, such as `v0.1.0`. After every check passes, the workflow pushes the package to NuGet and creates a GitHub release with generated notes and the same package. Each runs in its own job, so you can rerun a failed one alone. The CI scripts live in `eng/tasks/ci`.

`.github/workflows/docs.yml` deploys the documentation site from the tagged commit after every job of the tag's build succeeds, so the site matches the latest release. To publish a documentation fix sooner, run that workflow by hand. A manual run deploys the branch it runs on, which may document unreleased changes.

To try a local package, run `mise run pack`. It writes the package to `artifacts/nupkg`. Install it with `dotnet tool install ThomasFazzari.RoslynBridge --tool-path DIRECTORY --add-source artifacts/nupkg --version 0.0.0-dev`.

## License notices

The package contains `NOTICE` and `THIRD_PARTY_NOTICES.md`. It ships the assemblies of its dependencies, so update `THIRD_PARTY_NOTICES.md` whenever a package is added, removed or upgraded to a version with a different license. `mise run notices:check` compares the packages listed there with the packages the tool ships, and `mise run check` runs it.
