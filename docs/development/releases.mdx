The bridge ships as a native ahead-of-time (AOT) executable for each platform. Tests run on the .NET runtime, and the build workflow in `.github/workflows/ci.yml` also tests each native executable against Roslyn.

## Native builds

Publish with `RUNTIME_ID=osx-arm64 mise run publish`, using the runtime identifier for your platform. Output goes to `artifacts/native`. Native compilation requires the [platform build tools](https://learn.microsoft.com/dotnet/core/deploying/native-aot/#prerequisites).

Set `ROSLYN_BRIDGE_TEST_EXECUTABLE` to the absolute path of the published executable, then run `mise run test-integration` to test it against Roslyn.

## Publishing

Tag a commit of `master` whose `ci-ok` check passed, and push the tag, such as `v0.1.0`. The workflow publishes the release and the [NuGet packages](#nuget-packages) after every check passes, in separate jobs. A failure in one job does not stop the other, and you can rerun a failed job on its own. Each release contains one executable per platform, `LICENSE`, `NOTICE`, `THIRD_PARTY_NOTICES.md`, `DOTNET_RUNTIME_NOTICES.txt` and `SHA256SUMS`, which lists the checksum of every other file. The CI scripts live in `eng/tasks/ci`.

`.github/workflows/docs.yml` deploys the documentation site from the tagged commit after every job of the tag's build succeeds, so the site matches the latest release. To publish a documentation fix sooner, run that workflow by hand. A manual run deploys the branch it runs on, which may document unreleased changes.

## NuGet packages

The bridge is also a .NET tool on nuget.org with the package ID `ThomasFazzari.RoslynBridge`. Package IDs that start with `Roslyn` are reserved on nuget.org, so the ID uses the owner name. The installed command is still `roslyn-bridge-mcp`. The tool package only points to one runtime package per platform. A runtime package is named `ThomasFazzari.RoslynBridge.<rid>`, where `<rid>` is the runtime identifier, such as `osx-arm64`. It holds the native executable, `NOTICE` and the runtime notices, without debug symbols. `src/RoslynBridge/RoslynBridge.csproj` defines the metadata and the platforms.

Native AOT cannot cross-compile, so each native job packs the runtime package of its own platform with `mise run pack`. This runs on every build, so each runner proves its package before a release. On a tag, the job uploads the package as `nupkg-<rid>` and the executable as `native-<rid>`.

On a tag, the `nuget` job downloads the runtime packages and packs the tool package. `mise run ci:nuget` then pushes the runtime packages first and the tool package last, so the tool package never points to a missing package. A push that nuget.org refuses fails the job.

To try a local build, run `RUNTIME_ID=osx-arm64 mise run pack` with your runtime identifier, then `mise run pack` for the tool package. Packages go to `artifacts/nupkg`. Install them with `dotnet tool install ThomasFazzari.RoslynBridge --tool-path DIRECTORY --add-source artifacts/nupkg --version 0.0.0-dev`.

### Trusted publishing

The `nuget` job uses trusted publishing, so the repository holds no NuGet API key. The job asks GitHub for an identity token with the permission `id-token: write`. `NuGet/login` swaps it for an API key that lasts one hour. Set this up once before the first release:

1. On nuget.org, open Trusted Publishing from the account menu and add a policy. Use the owner `thomas-fazzari`, the repository `roslyn-bridge-mcp` and the workflow file `ci.yml`. Leave the environment empty. Set the package patterns to `ThomasFazzari.RoslynBridge` and `ThomasFazzari.RoslynBridge.*`, and allow new packages as well as new versions.
2. In the repository settings, add the secret `NUGET_USER` with the nuget.org user name. Use the profile name, not the email address.

## License notices

The executable embeds `NOTICE`, `THIRD_PARTY_NOTICES.md` and the .NET runtime notices, and prints them with `roslyn-bridge-mcp licenses`. The build takes the runtime notices from `THIRD-PARTY-NOTICES.TXT` in the restored `Microsoft.DotNet.ILCompiler` package and fails when the file is missing. Publishing copies it to the output as `DOTNET_RUNTIME_NOTICES.txt`. Native executables contain their dependencies, so update `THIRD_PARTY_NOTICES.md` whenever a package is added, removed or upgraded to a version with a different license. `mise run notices:check` compares the packages listed there with the packages the executable ships, and `mise run check` runs it.
