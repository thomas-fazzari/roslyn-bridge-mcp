Roslyn Bridge MCP is a .NET tool that serves C# tools over the Model Context Protocol (MCP). It starts the official Roslyn language server, keeps it in sync with the workspace files and turns tool calls into Language Server Protocol (LSP) requests.

## Design rules

- Keep the bridge standalone and usable from any MCP client.
- Use the official [MCP SDK](https://csharp.sdk.modelcontextprotocol.io/) for the tools and [StreamJsonRpc](https://microsoft.github.io/vs-streamjsonrpc/) for Roslyn.
- Reserve standard output for MCP messages. Send logs to standard error.
- Run in invariant globalization mode, so behavior does not depend on the machine's culture.
- Before applying Roslyn changes, check that each file still matches the version used to compute them.
- `.gitignore` is an allowlist. Allow each new project path explicitly.

## Tool changes

Tool names, parameters, result lines and error codes are a public contract that agents and their instructions depend on. Change one only when the gain justifies breaking them. A tool change reaches these places:

- The tool class in `src/RoslynBridge/Tools`, marked `[McpServerToolType]`. `Program.cs` registers every such class in the assembly.
- `ToolDescriptions`, which holds the parameter descriptions and the server instructions that clients pass to the model.
- [Usage](../usage.mdx), which documents parameters, results and errors.
- `docs/public/llms.txt`, the plain-text reference for agents.
- The agent guidance in `README.md`, [Getting started](../getting-started.mdx) and `AGENTS.md`, when it names the tool or action.
- A unit test for the contract, and an integration test when the behavior depends on Roslyn.

Then run `mise run test-integration` and `mise run docs:check`.

## Roslyn extension

`src/RoslynBridge.Extension` runs inside the Roslyn process. The bridge activates it once Roslyn has loaded the workspace, then sends it reference queries for `references`, `reads` and `writes`. This avoids the 500 ms batching delay of the `textDocument/references` handler.

The extension matches that handler's results by calling internal Roslyn members through reflection, because the public search also lists the references of sibling overrides. It also marks the references that write the symbol, as `textDocument/documentHighlight` does. When activation or a query fails, the bridge logs a warning and uses `textDocument/references` until the next session. It then sends one `textDocument/documentHighlight` request per file to tell reads from writes. That is slower, and it misses a reference when the file's first one goes through another symbol, such as an interface member.

The extension also answers `callers`. The `callHierarchy/incomingCalls` handler keeps only direct calls, so it misses every call made through an interface or base member. The extension lists those too, and names the member they go through. Without the extension, `callers` falls back to that handler and lists direct calls only.

The extension alone answers `symbols` with `unused`, through a workspace message that takes the selected files. LSP has no request for unused code, and a reference search over LSP would cost one round trip per declaration. The handler searches the references of every candidate declaration in parallel, then marks as dead the greatest set of candidates that only dead code or test projects use, so code that only uses itself stays dead. A failed search keeps its candidate, since deleting live code costs more than keeping dead code. A failure of the whole message returns `lsp_error` and leaves the reference and caller handlers active.

`RoslynServerVersion` in `Directory.Packages.props` sets the server that `setup` installs, that the CI tests against and that the extension compiles against. After changing it, run `mise run test-integration` on every platform the CI covers, since Roslyn changes its path handling between versions.
