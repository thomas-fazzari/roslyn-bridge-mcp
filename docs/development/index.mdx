Roslyn Bridge MCP is a .NET tool that serves C# tools over the Model Context Protocol (MCP). It starts the official Roslyn language server, keeps it in sync with the workspace files and turns tool calls into Language Server Protocol (LSP) requests.

## Design rules

- Keep the bridge standalone and usable from any MCP client.
- Use the official [MCP SDK](https://csharp.sdk.modelcontextprotocol.io/) for the tools and [StreamJsonRpc](https://microsoft.github.io/vs-streamjsonrpc/) for Roslyn.
- Reserve standard output for MCP messages. Send logs to standard error.
- Run in invariant globalization mode, so behavior does not depend on the machine's culture.
- Before applying Roslyn changes, check that each file still matches the version used to compute them.
- `.gitignore` is an allowlist. Allow each new project path explicitly.

## Tool changes

Tool names, parameters, result lines and error codes are a public contract that agents and their instructions depend on. Change one only when the gain justifies breaking them. A tool change reaches these places:

- The tool class in `src/RoslynBridge/Tools`, marked `[McpServerToolType]`. `Program.cs` registers every such class in the assembly.
- `ToolDescriptions`, which holds the parameter descriptions and the server instructions that clients pass to the model.
- [Usage](../usage.mdx), which documents parameters, results and errors.
- `docs/public/llms.txt`, the plain-text reference for agents.
- The agent guidance in `README.md`, [Getting started](../getting-started.mdx) and `AGENTS.md`, when it names the tool or action.
- A unit test for the contract, and an integration test when the behavior depends on Roslyn.

Then run `mise run test-integration` and `mise run docs:check`.
