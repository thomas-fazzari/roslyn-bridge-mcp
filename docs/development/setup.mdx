Prerequisites: Git, Bash and [mise](https://mise.jdx.dev). mise installs the .NET SDK, Bun, CSharpier, hk, ShellCheck and shfmt at the versions pinned in `mise.toml` and `mise.lock`. On Windows, use Git Bash. Run commands from the repository root.

```sh
mise install
mise run install
mise run hooks:install
```

`hk.pkl` defines the Git hooks for [hk](https://hk.jdx.dev).

| Hook       | Runs                                                                                                                                                                           |
| ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| pre-commit | The formatters and linters of `hk.pkl` on staged files, then stages their fixes                                                                                                |
| commit-msg | `eng/tasks/commit-msg.pl`, which checks the [commit message](contributing.mdx#checks)                                                                                          |
| pre-push   | The same steps in check mode on pushed files, `build` when C# or build files change, `docs:build` when the documentation, `README.md`, `AGENTS.md` or `CONTRIBUTING.md` change |

## Editor

In VS Code, open `roslyn-bridge.code-workspace`, on the host or in the dev container. It holds the editor settings, the recommended extensions and the tasks.

## Dev container

`.devcontainer` describes an Ubuntu container with mise. On creation, it installs the tools from `mise.toml`, restores the dependencies and installs the Roslyn language server for the integration tests.
The container keeps `node_modules` in a Docker volume, because Bun installs platform-specific binaries that would break the host checkout. Build output in `bin` and `obj` is shared with the host, so the first build on the other side restores again.

## Local settings

Put local environment variables in the `[env]` table of `mise.local.toml`. mise loads it for every task and Git ignores it. Existing environment variables take precedence. MCP clients launch the bridge with their own environment, so it does not see these variables.

## Builds

Builds use Debug by default. Run `CONFIGURATION=Release mise run build` for a release build. Stop any bridge process that uses the build output before rebuilding it.
